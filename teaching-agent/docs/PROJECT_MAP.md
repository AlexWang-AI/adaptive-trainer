> 目标：明确「这个产品到底在做什么」「一共几个 agent、各自边界在哪」「还缺什么」。
> 配套：`docs/AGENT_STANDARD.md`（怎么做 agent）、`backend/contracts.py`（消息格式）、`backend/curriculum.py`（知识点底座）
> 2026-11-01

## 1. 产品是什么（一句话）

> **学生带着一个目标进来（比如「两周把极限学扎实」），系统给他一条能执行、能量化、能验收的路径，并在每一步告诉他「现在做什么、离掌握还差多少」，直到他能独立做出教辅原题 + 独立做出同构变式题为止。**

不是聊天机器人，不是题库。核心交付物是**「掌握」这个判定**，以及通向它的路径。

---

## 2. 掌握标准（全项目唯一口径，不许各 agent 自己定义）

一个知识点算「掌握」，必须同时满足：

| 条件 | 判定方式 | 谁负责产出证据 |
|---|---|---|
| 独立做对 ≥2 道教辅原题 | 学生作答，判分节点给结论 | `quiz` + `judge` |
| 独立做对 ≥1 道同构变式 | 换数字/换形态，同考点 | `quiz`（变式模式）+ `judge` |
| 步骤无卡顿、无提示 | 学生自述或耗时超限则不算 | 前端记录 + `judge` |
| （综合单元）做对 1 道综合题 | 跨知识点、对标考研难度 | `exam` + `judge` |

量化口径：

```
kp.mastery = 0.4 × min(independent_solves / 2, 1)
           + 0.4 × min(variant_solves / 1, 1)
           + 0.2 × (综合题得分率, 若该单元要求)

单元通过：该单元内所有 kp 的 mastery ≥ 0.9，且至少 1 次「独立 + 变式」全过
```

「从当前水平到 90%」= 目标知识点集合里，mastery ≥ 0.9 的 kp 占比 ≥ 90%。

|---|---|---|---|---|
| 1 | `planner` | 路线规划（总指挥 / 锚点） | 把目标拆成单元序列 + 每单元验收标准 | ✅ 本次新建 |
| 2 | `teach` | 主讲 | 在**当前单元**内讲明白，不越界、不跳章 | ✅ 已有（variant B） |
| 3 | `quiz` | 出题 | 基于本轮教学正文出一道题 / 一道变式 | ✅ 已有，待优化 |
| 4 | `sideqa` | 负分支提问 | 主干对话里冒出来的小疑问，开副分支讲透并归档 | ⬜ 下一步 |
| 5 | `exam` | 综合题 | 单元收尾时出跨知识点综合卷 | ⬜ 下一步 |
| — | `judge` | 判分（确定性） | 客观题比对 + 数学等价判断 | ✅ 已有，待加固 |
| — | `formatter` | 卡片（确定性） | 把结构化产物变成 UI 卡片 | ✅ 已有 |

### 边界（最容易越界的地方）

| Agent | ✅ 可以做 | ❌ 绝对不能做 |
|---|---|---|
| `planner` | 定顺序、定验收、估算轮次 | 讲课、出题、判分 |
| `teach` | 讲解、举例、追问、收尾 | 决定「下一步学什么」、出题、打分 |
| `quiz` | 出题、指定考点、给解析 | 决定讲什么、评价学生整体水平 |
| `sideqa` | 回答支线小问题、标注薄弱点 | 改变主干进度、把支线内容写进主干历史 |
| `exam` | 组卷、跨知识点配比、给踩分点 | 判分（判分永远是 `judge`） |
| `judge` | 判对错、归因、写错题本 | 生成内容（它不调 LLM 出文本） |

**判分永远不交给 LLM 自由发挥**——`judge` 只做字符串归一化 + 数值/符号等价判断；需要语义判断时，必须输出可审计的证据（踩分点命中表），不是一句"我觉得对"。

## 4. 拓扑与信息流

```
                        ┌─────────────────────────┐
                        │  planner（锚点 / 路线）   │
                        │  单元序列 + 验收标准      │
                        └───────────┬─────────────┘
                                    │ CurrentUnit { kp_ids, exit_test }
                                    ▼
   ┌────────────────────────────────────────────────────────┐
   │                    tutor（hub / 会话）                   │
   │  持有 thread（本会话）+ StudentProfile（跨会话）           │
   └───┬───────────┬──────────────┬──────────────┬──────────┘
       │           │              │              │
       ▼           ▼              ▼              ▼
    teach       quiz           sideqa          exam
   （讲）      （出题）        （副分支）      （综合卷）
       │           │              │              │
       └───────────┴──────┬───────┴──────────────┘
                          ▼
                      judge（确定性判分）
                          │
              ┌───────────┴────────────┐
              ▼                        ▼
        MistakeEntry（错题本）    KpState 更新（掌握度）
                                        │
                                        ▼
                              planner 重新排后续单元
```

**铁律**：能力节点之间没有边。`quiz` 看不到 `teach` 的历史，`teach` 看不到题目和答案，`sideqa` 与主干完全隔离。

## 5. 消息格式（都在 `backend/contracts.py`）

| 消息 | 生产者 → 消费者 | 关键字段 | 记忆 |
|---|---|---|---|
| `Unit` / `StudyPlan` | planner → hub | `kp_ids`、`exit_test`、`est_sessions` | 跨会话（存 DB） |
| `TeachOut` | teach → hub → 前端 | `reply_markdown`、`check_question` | 会话内近 3 轮 |
| `QuizOut` | quiz → hub → 前端 | `stem`、`options`、`answer`、`source_quote` | 无（纯函数） |
| `Judgement` | judge → hub → quiz/planner | `correct`、`error_type`、`kp` | 无 |
| `SideAnswer` | sideqa → 错题本 | `answer_markdown`、`kp_tag`、`archive_card` | 副分支，用完即弃 |
| `ExamPaper` | exam → judge | `questions[]`、`rubric_points[]` | 无 |
| `KpState` | judge → StudentProfile | `mastery`、`independent_solves`、`variant_solves` | **长期（DB）** |
| `MistakeEntry` | judge/sideqa → 错题本 | `kind`、`root_cause`、`correct_model` | 长期（DB） |

**铁律**：字段名不许在 agent 之间"约定俗成"，必须在 `contracts.py` 里有类型；改字段名 = PR + review。

## 7. 教材管线（必须先解决的事实）

桌面上的《张宇基础 30 讲（高数）》PDF：**586 页、扫描件、无文字层、无书签**（已实测：第 50 页抽取字符数为 0，书签只有 1 条）。

所以不能靠 `pypdf` 直接抽文本，管线必须是：

```
PDF 页图 → OCR(中文+数学公式) → 结构化切分 → 三类资产
                                          ├── 目录树（讲/章/节）
                                          ├── 知识点条目（映射到 curriculum kp id）
                                          └── 题目库（题干/选项/答案/解析/来源页）
```

三类资产的落地要求：

| 资产 | 格式 | 用途 |
|---|---|---|
| 目录树 | JSON：`{lecture, section, page_start, page_end}` | planner 的 `textbook_ref` |
| 知识点映射 | CSV/JSON：`kp_id → 页码区间` | 让学生知道「翻哪几页」 |
| 题目库 | JSONL：`{id, source_page, type, stem, options, answer, explanation, kp_ids}` | quiz / exam 的真实题源 |

OCR 建议：先跑 10 页验证公式识别质量，再决定全量方案（公式错的 OCR 比没有更糟）。
**在 OCR 完成前，`curriculum.py` 是知识点唯一权威，agent 不许引用页码。**

## 8. 风险清单（按概率排序）

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| 题库/教材解析不出来（扫描件 + 公式） | 高 | 综合题只能靠生成，难度不可控 | 先跑 10 页 OCR 验证；不行就用「生成 + 人工抽检 20 题」 |
| 判分误判（`x=2` vs `2`、`\frac{1}{2}` vs `0.5`） | 高 | 学生会认为系统乱判，信任崩塌 | 上 sympy 等价判断；判错可申诉并留证据 |
| 掌握度模型太粗（只数做题数） | 中 | "90%" 变成数字游戏 | 加入变式题 + 综合题 + 时间/提示维度 |
| 5 个 agent 接口漂移 | 中 | 第 4 周开始返工 | `contracts.py` 冻结 + contract test |
| 会话状态丢失 | 中 | 学生换天回来重新开始 | `SqliteSaver` + `student` 表 |
| 时间不够（5 周做完 5 个 agent） | 中 | 阉割功能 | 砍 `exam` 的综合卷评分，只做组卷 |

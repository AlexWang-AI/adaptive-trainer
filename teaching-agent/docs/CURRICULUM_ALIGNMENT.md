# 知识架构与《张宇基础30讲》对齐报告

> 触发问题：「目前知识架构必须严格和这个（张宇基础30讲知识树）契合，讲课的内容也要以这个为标准 —— 有没有做到？」
> 结论：**没有**。截至本轮之前，应用里跑的是一份**手写的 69 点 / 12 讲**课程表，
> 和桌面上的《张宇基础30讲》知识树（18 讲 / 232 点 / 375 条结论）**没有任何代码关联**，
> 讲课提示词里也没有一句教材原文。本轮把这条链路接上了，下面是改动与证据。

---

## 一、核查：之前的差距（事实，不是印象）

| 维度 | 之前（v3 交付时） | 教材树（`textbook/tree/`） | 差距 |
|---|---|---|---|
| 讲次 | 12 个自拟章节（lim / der / app / int / mv / di / ode / ser / vec / mi） | **18 讲**，讲名与教材目录一致 | 讲次划分不同，且只有高数，无「第7讲 物理应用」这类独占讲 |
| 知识点 | 69 个，手写在 `curriculum.py` 的 `_RAW_KPS` | **232 个**（L2 节点），带 L3 要点 1068 条 | 覆盖率 30% |
| 结构层级 | 两段（章 → 点） | **三层（讲 → L1 分支 71 个 → L2 知识点）** | 侧栏看不到「分支」，也看不到「必考/高频/边缘」 |
| 教材依据 | `textbook_ref` 字段为空，注释写「等 OCR 完成」 | 每个点都有考纲句 + 要点 + 教材例题 + 分支结论 | 讲课没有任何教材约束 |
| 出题依据 | 模型自由生成，`source_quote` 只校验「是不是讲义原句」 | 144 个题型、124 条秒杀/陷阱、581 个教材例题 | 题目与教材脱节 |
| 数据 id | `lim.definition` 这类手写 id | 无 id（树只有名字） | 需要自己定义并迁移 |

补充事实（这轮查证的）：

- 桌面 `数一教辅/` 里三个 PDF：高数 586 页（**已有 OCR 版**，流水线跑过）、线代 213 页、概率 173 页；
- 线代 / 概率两份 PDF **没有文字层**（前 6 页抽出 0 字符），书签也是图片名（`image0000167B`），
  必须先 OCR 才能建树 —— 这是它们至今不在树里的唯一原因；
- `textbook/tree/` 的 `index.json` 写「kps 227」，但按其自身 weighted 文件逐个数是 **232**，
  index 是旧的统计；本报告与运行时都以 weighted 文件为准。

## 二、架构：树 → 编译 → 运行时

```
textbook/tree/                            （流水线产物，会随重跑漂移，不直接读）
  lecture_01..18_weighted.json  ──┐       讲 / 分支 / L2 知识点 / L3 要点 / 结论
  lecture_XX_types.json         ──┤       144 个题型（steps + 关联知识点名）
  lecture_XX_extras.json        ──┤       124 条秒杀技巧 / 陷阱（enhances = 知识点名）
  lecture_XX_examples.json      ──┘       教材例题原文（mapping 里挂到知识点名）
                                   │
                    scripts/build_curriculum.py   ← 一次性编译，id 在这里定死
                                   ▼
                    backend/curriculum_data.json   （495 KB，运行时唯一来源）
                                   │
                    backend/curriculum.py          ← 只读这份 JSON
                     ├─ CHAPTERS   18 讲（含 blocks）
                     ├─ KP_TABLE   232 点 + 要点/结论/例题/题型/提速
                     ├─ order_index / prereq / whitelist（旧 API 全部保留）
                     └─ textbook_block(kp_id) → 578 字左右的「教材依据」文本
                                   │
        /api/curriculum（三级树） /api/kp_detail（单点细节） /api/teach_stream（讲课）
```

### 2.1 为什么编译成 JSON，而不是运行时直读树

- 树是流水线产物，重跑会改字段、改顺序；**id 必须稳定**，否则 `student_kp` 里的历史记录会错位。
- 编译时一次性定死 `id / 顺序 / 权重`，运行时不依赖 `textbook/` 目录是否存在（部署只要 JSON）。
- 编译脚本自带自检：id 唯一、每点有考纲、每个点要么有要点要么有例题（否则报「讲解没有依据」）。

### 2.2 id 规则

```
l01-b02-k01
│    │    └── 该分支第 1 个知识点（L2）
│    └─────── 第 1 讲第 2 个分支（L1）
└──────────── 第 1 讲
```

- 讲次来自教材（1~18），分支和知识点的序号来自 weighted 文件里的顺序；
- 考频 `exam_weight`：分支档 `must→5 / high→4 / edge→3`，前端「高频」标签、雷达、排序都吃这个字段；
- 前置 `prerequisites`：**讲内线性**（同一讲里上一个点），讲内第一个点无前置 —— 不跨讲强绑，
  这样任何一讲都能从第一节点开讲，而「下一站」仍然是教材目录顺序。

### 2.3 三级侧栏

讲（可折叠）→ 分支（可折叠，右侧显示 `必考/高频/边缘` 与该分支通关数）→ 知识点（带通关勾、高频标）。
默认只展开「下一站」所在的那一支 —— 232 个点全摊开会淹没视线。

## 三、讲课：把教材依据塞进提示词，并让它可验证

### 3.1 注入内容（`curriculum.textbook_block`）

```
第1讲 函数极限与连续（必考）· 计算（求极限的方法）
【考纲】掌握极限的性质及四则运算法则
【教材要点】①适用条件：各项极限均存在且分母极限不为零  ②常见易错：分母极限为零时不能直接使用 …
【本讲结论】①极限的四则运算法则：… ②洛必达法则：… ③两个重要极限：…
【教材例题】例1.14、例1.21、例1.25、例1.27
【对应题型】无穷小运算求极限：识别各因子是否为无穷小或有界量 → …
```

约 578 字（上限 900，schema 上限 1400）。选取规则：

- 要点取该 L2 节点的 L3 子项，最多 6 条；
- 结论取**所属分支**的结论，按「与知识点名/要点的二元组重合度」排序取 3 条
  （用单字重合会被虚词带偏，实测二元组才认得出「四则运算」这类术语）；
- 题型按同样方式挑最贴的一个（否则会给「四则运算」配「夹逼准则」）；
- 极少数节点（如「唯一性」）没有要点也没有例题，靠分支结论兜底，编译时标 `thin` 并计数（当前 1 个）。

### 3.2 提示词约束

系统提示词里新增一段，明确「讲解以它为准，不允许改结论」，并给了四条硬要求：
只讲这一层；优先用教材例题当锚点；教材之外的延伸最多一句且标注「教材之外」；不许引入与结论冲突的捷径。

### 3.3 source_quote 口径（一个必须修的坑）

接入教材后，模型开始把 `source_quote` 写成**教材原文**（而不是讲义原文），
而原来的校验只认「讲义里逐字存在」→ 每轮重生成 2 次，token 从 1100 涨到 3500、耗时从 7.3s 涨到 19s。
（`runs/trace.jsonl` 里连续三条 `attempts: 3, ok: false`，报错全是「source_quote 不是讲义原句」。）

修法两条：

1. 提示词说清楚：优先从【教材依据】逐字取，其次讲义正文，两者都不许改写；
2. 校验放宽到「讲义 **或** 教材依据里逐字存在」（去标点空白后比前 8 字）。

修完单轮回到 **7.2s / 2154 token**（2 次采样），TTFT 中位数 952~1221 ms。

## 六、还没做到的（明确记录）

1. **线代 / 概率不在树里**。两份 PDF 无文字层，需要 OCR（MinerU，实测约 38 s/页 × 386 页 ≈ 4 小时 CPU）。
   在 OCR 完成前**故意不建空节点** —— 有节点没教材，等于又回到「讲课靠模型自由发挥」。
   完成后按同一 schema 追加 `lecture_19..30`，课程表自动变成 30 讲，前端不用改。
2. **出题还没接题型层 / 提速层**。这轮只把 `types` / `extras` 编译进了 `curriculum_data.json`（并挑一个进提示词），
   真正的「按题型出题」还没做：下一步应该是 `/api/practice_more` 和讲练合一的 3 题直接从 `types[].steps` 生成，
   教材例题（581 条原文已在 `examples_lecture_XX.json`）作为「同源题」优先复用。
3. **结论是分支级的**，不是知识点级。同一个分支下 3~8 个点共享同一批结论，
   所以讲义里会出现「同一分支其他点」的结论（例如讲四则运算时也带上洛必达）。
   现在用二元组排序压低了噪声，但要彻底解决，得让流水线把结论下沉到 L2。
4. **`index.json` 的统计是旧的**（227 vs 232），没改流水线产物，只在编译时以 weighted 为准并在自检里打印。

## 九、把「教材」真正接到讲课与出题上（2026-11-10）

前八节解决的是「知识架构对齐」；这一节解决「内容以教材为准」——两者缺一不可：
树再准，讲课时模型不引用它，等于没接。

### 9.1 教材例题原文进提示词

之前只有例题**编号**（例1.14、例1.21），模型知道有这题但看不到题面，只能自己编。
现在 `build_curriculum.py` 会从 `examples_lecture_XX.json` 抽题面（在「解/分析/答案」处截断，
去掉开头的例号），挂到知识点的 `example_texts`：

```
【教材例题】例1.14：已知 $\lim_{x \to 0}\frac{f(x)}{x^2}$ 存在，且函数…   例1.21：设 $\lim_{x\to0}\frac{\sin x}{e^x-a}(\cos x-b)=5$，则 b=
```

覆盖率：**191 / 232** 个知识点带例题原文（其余是纯概念节点，教材本来就没有例题）。
教材依据块从 578 字涨到 **835 字**，TTFT 从 ~1.2s 涨到 **1.2~1.5s**（预算 2000ms）。

### 9.2 题型层接入出题（两个入口都改）

| 入口 | 改法 |
|---|---|
| `/api/practice_more`（再练一组） | 把该知识点的 `types`（题型名 + 题干特征 + 解法步骤）、`example_texts`、分支结论一起塞进 prompt；每张卡必须带 `type_name`，**≥2 张命中题型**才算过，否则重试一次 |
| 讲练合一的 3 道题 | 系统提示词明确「若【教材依据】给了【对应题型】，三道题的解法必须分别落在该题型的步骤上」，`COMPACT_SCHEMA` 里加了 `type_name` 字段 |

讲练合一这条**没有做「不达标就重试」**，因为主链路一次生成 7~9 秒，为一个标签重跑整轮不划算。
改成确定性兜底 `_auto_tag_types()`：模型忘了写 `type_name`，但 `why_this_question` / `stem` 里
点了题型名（「按夹逼准则…」），就把标签补上；纯概念节点则一律清空。
命中数写进 trace（`types_tagged`、`textbook_chars`），回归时看日志就能发现退化。

配套两个工程加固：

- `_finalize_card()`：一张卡缺 `explanation`/`why_this_question` 就**补默认值**而不是整批重试
  （原来 3 张里坏 1 张就重生成，单次多花 1500~2000 token）；超长字段按 pydantic 上限截断。
- 纯概念节点（10 / 232，如「无穷大的定义」）没有题型，模型会自己编一个 `type_name` ——
  API 层统一清空，保证字段语义干净。

题卡头部在知识点名后面显示一个胶囊标签（`title="教材题型：…"`，`data` 可被 e2e 选中），

### 9.4 已知边界

- 10 个纯概念节点没有教材题型 → 出题退回「按要点自由出题」，不强行套题型；
- 题型与知识点的挂接是教材流水线按**知识点中文名**做的，一个题型可能挂到多个知识点
  （例如「夹逼准则求极限」同时挂在「极限四则运算规则」下），所以判断题型的贴合度时看的是
  「是否属于该知识点的题型清单」，不追求唯一；
- 线代 / 概率暂缓（扫描件无文字层，OCR 方案已按用户要求停掉），等文字版再并入。

## 十、知识树在界面上的完整呈现（2026-11-10）

### 10.1 问题

侧栏原来只到「知识点」这一层：**「七种未定式的计算」只剩一个点**，
而知识树里它下面明明有 0/0、∞/∞、0·∞、∞-∞、0⁰、1^∞、∞⁰ 七种未定式，各带解法。
结论层（375 条）、题型步骤、教材例题在界面上全是隐形的 —— 相当于**用 UI 把知识图谱压扁了**。

原则更正：**agent 服务于已清洗好的知识图谱，不是让知识图谱迁就界面。**

### 10.2 现在的四层 + 三类元数据

```
讲（18）                     第1讲 函数极限与连续           3/22
└ 分支（71）                 计算（求极限的方法）  必考 2/8
  └ 知识点（232）            ▸ 七种未定式的计算
    └ 教材要点（1061）        · 0/0 型：洛必达或泰勒展开；先判类型再求导   ← 点它 = 只讲这一条
      ├ 题型（144，带步骤）   题型：1^∞型未定式求极限 → 取对数化为0·∞型 → …
      ├ 教材例题（581）       教材例题：例1.14 例1.15 例1.24 例1.28 例1.31 例1.32
      └ 提速技巧（124）       提速：洛必达前先等价化简
   本分支结论（375）          ▸ 本分支结论（6）→ 1. 极限的四则运算法则… 2. 两个重要极限…
```

- 知识点右侧的小箭头展开教材细节，**按需拉 `/api/kp_detail`**（不塞进 `/api/curriculum` 初始负载）；
- 分支末尾的「本分支结论」可展开看原文（`_tree` 里新增 `conclusion_list`）；
- **每个要点都是可讲的**：点一条 = 以「知识点｜子项」开讲，讲义与 3 道题只围绕这一条。

### 10.3 为了「不丢信息」改的三处

| 位置 | 改动 | 原因 |
|---|---|---|
| `build_curriculum.py` | 上限从 12/4/3 提到 40/10/10（要点/题型/提速） | 原树单点最多 18 个要点、6 个题型、6 条提速，原来被截断 |
| `api_server._tree` | 分支返回 `conclusion_list`（≤16 条原文） | 结论层原来只返回个数 |
| `TeachingRequest / TeachStreamBody` | 新增 `focus` 字段，三层透传（前端 → 代理 → 后端 → 提示词） | 子项要能单独开讲，而不是只能讲整个知识点 |

### 10.5 已知边界

- 原树里个别节点有重复要点（「七种未定式」下两条 `x=e^{ln x}` 公式），**按原样呈现**，不替知识图谱做清洗；
- 上标字符（0⁰、∞⁰）在某些字体下显示为 `0ᵖ`，是字体缺字，不是数据错；
- 更细的「颗粒化」树（`textbook/tree/granular/`，11 讲）和 v3 的 L4 步骤还没进界面——
  它们与 `types.steps` 有重叠，等确认哪份是权威版本再接；
